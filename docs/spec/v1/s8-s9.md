# S8 / S9 spike results

Tested on Hyprland 0.56.2, swaync 0.12.6-1, swayosd 0.3.2-1. S8 ran in a nested Hyprland
(tests/ws/nested.sh via tests/keys/lib.sh, own instance only); the live session was untouched.

## S8: do `code:NN` Lua binds show in `hyprctl binds -j` with keycode/modmask?

Outcome: PARTIAL. Decision entry below.

Evidence (fixture `tests/desktop/fixtures/s8-nested-binds.json`, real capture, 72 binds, empty
configerrors): all 26 `code:` binds are registered and `modmask` is correct (SUPER=64,
+SHIFT=65, +ALT=72, +ALT+SHIFT=73, +CTRL=68). But for Lua binds `key` is `""` and `keycode` is `0`:
the keycode is NOT reported. `dispatcher` is `__lua` and `arg` is an opaque closure id.

Decision: the cheat sheet and keys-lint take the key from the Lua source (static parse) and match
runtime binds by `description` + `modmask`, never by key or keycode. The `seclegion-keys: `
description prefix is the reliable identity. `cheatsheet.runtime_entry` falls back to
`code:<keycode>` only when `keycode` is non-zero, which never happens for these binds, so merging
runtime binds by key signature may add duplicate blank-key rows (follow-up, not fixed here).
Runtime `arg` is not usable as a command for Lua binds.

## S9: swaync margin and swayosd custom message

- swaync margin: PASS, with a limit. 0.12.6 documents only `control-center-margin-top/right/bottom/left`
  (man swaync(5), /etc/xdg/swaync/configSchema.json) and we set exactly those four. There is no
  popup margin key, so the popup offset stays a CSS padding on `.floating-notifications.background`
  (already in style.css). Not checked visually (no notifications sent to the owner's session).
- swayosd custom message: PASS. `swayosd-client --help` lists `--custom-message <text>`,
  `--custom-icon`, `--custom-progress`, `--custom-segmented-progress`, `--custom-progress-text`.
  The shipped `desktop/osd/seclegion-osd` is a dunstify shim and uses no swayosd flag today.
