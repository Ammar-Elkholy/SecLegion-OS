## Round 1b — Legion → Sec (independent position, before seeing Sec's draft)

**Verified on host:** calamares not in repos; archinstall 4.5 in extra; limine, grub-btrfs, snap-pac, swtpm, tesseract, sbctl, edk2-ovmf, qemu-desktop in extra; swtpm/tesseract/expect not installed on host; /tmp is 7.5 GB tmpfs (too small for ISO build); 12 cores / 14 GiB.

**Non-negotiables (each from a past failure):**
1. No PASS without an artifact — TESTING.md generated from `evidence/<test-id>/<iso-sha256>/`; CI fails on hand-edited or dangling claims.
2. Install ≠ Live by construction — different cmdline → different systemd target; a test asserts different end states.
3. No NOPASSWD ALL, no `xhost +`, no empty passwords, no root-getty fallback; root via one narrow audited backend; failures show a branded error screen with log path.
4. Installed initramfs built for the installed system — automated assertion: no archiso hooks, sd-encrypt present when LUKS.
5. No live-session leftovers on target — deny-list grep of installed rootfs.
6. Every package signed/verified; no `SigLevel Optional`; no binaries in git.
7. One daemon per role, enforced by a test against a role table.
8. Layer-by-layer, no milestone N+1 on a red milestone N.
9. Deterministic build with built-ISO lint (mode bits, no "Arch Linux" in boot configs, wants-symlinks, no `:latest`).
10. Destructive actions guarded and tested — Windows ESP files hashed before/after.

**Stances:** custom GTK4/libadwaita installer = thin UI over headless JSON-config backend (pinned archinstall lib); root via `seclegion-installd` (systemd, socket/D-Bus) + polkit; `pacstrap` from manifest with offline package cache (no squashfs copy); ISO boot = archiso `uefi.systemd-boot`, UEFI-only, text menu (graphical splash → 1.1); installed = systemd-boot + LUKS2 argon2id (sd-encrypt), snapper/snap-pac, rollback via ISO Rescue, ESP free-space check, never resize Windows ESP (GRUB+grub-btrfs alternative put to owner); official repos + one signed `[seclegion]` meta-package repo; AUR apps only with owner-approved reviewed PKGBUILDs; data-driven PCI-ID→driver table tested with recorded lspci fixtures; gaming as installer checkbox (multilib, lib32 Vulkan per GPU); build workdir on ext4, refuse fuseblk.

**Test strategy:** pytest + QEMU/OVMF, serial console + QMP screendump + tesseract OCR; test-only console boot entry generated by harness (not shipped); per-milestone proofs (M1 build lint → M2 boot menu text/timeout → M3 Install vs Live states → M4 install matrix incl. LUKS and Windows-fixture dual boot → M5 desktop/keybind injection/one notification → M6 tools/labs → M7 KVM, needs nested virt). HW-ONLY tests (NVIDIA/PRIME, hardware keys, suspend, Wi-Fi/BT/audio, Steam, Secure Boot) can never be PASS from a VM; need hardware-report evidence; mutation tests re-introduce old bugs to prove tests go red.

**Proposed 1.0 cut:** ship signed UEFI ISO, custom installer (single/dual boot, btrfs, optional LUKS2, Latin+Arabic), HW detection + report, owner's Hyprland desktop, Tier 1 tools, podman/distrobox, KVM NAT + isolated net, simple `seclegion-tools`, snapper/zram/rescue, gaming checkbox. **Defer:** adaptive theming everywhere, screensaver variants, AI toolset (ollama optional only), Kali/BlackArch labs (experimental at most), App Center, apt-get wrapper, GNOME, Burp/Caido containers, Secure Boot, BIOS, graphical boot splash.

**Questions for Sec:** (1) exact privilege boundary — units, socket/D-Bus, polkit IDs; (2) initramfs guarantee + assertion; (3) bootloader answers for argon2id / 100 MB Windows ESP / snapshot boot; (4) signed repo contents, key holder, which AUR apps get packaged and who maintains; (5) console oracle without debug cmdline + nested KVM; (6) strict milestone order + exit evidence; (7) automating one-daemon-per-role and no-leftovers + anti-hand-edit evidence schema; (8) explicit 1.0 cut list for the owner.

## Round 1a — Sec → Legion (Draft 1)

Full text: [sec-draft-1.md](sec-draft-1.md). Key positions:
- **Installer:** custom GTK4 wizard (unprivileged) → JSON install plan → `seclegion-installd` root D-Bus backend (`org.seclegion.Installer1`) using plain `sgdisk/cryptsetup/pacstrap/bootctl`. **Rejects archinstall lib** (hides commands PRD §11 wants shown). Alongside-install only into free space; never resizes Windows.
- **ISO boot:** GRUB gfxmenu (branded), UEFI-only, 6 entries each mapping to a distinct systemd target.
- **Privilege:** polkit rule for one action only, live user, per-boot random Live password, root locked.
- **Target:** `pacstrap` from manifest + offline signed cache; never squashfs copy.
- **Installed boot:** systemd-boot + UKIs, LUKS2 argon2id, XBOOTLDR solves 100 MB Windows ESP; no snapshot boot entries in 1.0 (rollback via Rescue).
- **Desktop:** one program per role (swaync, swayosd, hyprpolkitagent, awww, rofi, waybar, greetd+regreet); GNOME dropped.
- **Hardware:** data-driven `seclegion-hwdetect` rules (Turing+ → nvidia-open, older → nouveau with message), full linux-firmware, VM guest tools, community `seclegion-hwreport`.
- **Gaming:** first-class installer option in 1.0.
- **Milestones M0–M12** with automated + hardware gates; 1.1 = labs/containers/apt-compat; 1.2 = adaptive theming, screensaver variants, App Center, AI.
- **Disagrees with Legion on:** GRUB vs text menu (branding), archinstall lib, gaming in 1.0, lock + Logo screensaver in 1.0.
- **Asks Legion:** no-resize UX OK? OCR GUI tests flaky? move snapper spike to M4? full vs split firmware? cage vs sway kiosk for Arabic? random vs well-known live password?

## Round 2 — Legion → Sec (critique)

Full text: [legion-round-2.md](legion-round-2.md).
- **Concedes 3 of Sec's 4 disagreements:** GRUB gfxmenu on ISO, no archinstall lib, gaming in 1.0. **Holds narrowly** on screensaver (must be input-isolated from lock, else slips to 1.1).
- **8 blocking defects:** B1 polkit rule would give Try-Live processes unauthenticated disk wipe → only in Install mode; B2 offline-pinned base + online gaming/NVIDIA = partial upgrade → `-Syu` first; B3 Python ABI breakage on Arch Python bumps → private path + compat canary; B4 dev vs release signing keys + fingerprint gate; B5 `/etc/os-release` restored by `filesystem` upgrades; B6 "0 failed units" too weak → exact expected-units list; B7 UNVERIFIED items become spikes before dependents; B8 HW-only gates block release without attestation.
- **Answers:** no-resize OK for 1.0 only with a guide screen + BitLocker/Fast Startup/hibernation detection; OCR tests use serial signals, not sleeps; snapper spike before M4; full linux-firmware; sway kiosk if cage can't switch Arabic at runtime; per-boot random live password.
- **Escalations to owner:** no-resize dual boot UX; tiny Windows ESP (refuse vs own ESP); Live-mode install needs password; screensaver fallback; repo maintenance cost; Brave deferred / VS Code OSS.

## Round 3 — Sec → Legion (response + Draft 2)

Full text: [draft-2.md](draft-2.md).

## Round 4 — Legion → Sec (final verdict): SIGN-OFF-WITH-AMENDMENTS
No blocking defects remain. Amendments (all applied in [spec.md](spec.md)):
- Passwordless live model done safely: locked (not empty) live password, all live privileges owned by ISO-only `seclegion-live`; installer kiosk user has no sudo; no lock screen in Live; target always requires the user's password.
- Containment gates + mutation suite: any live package/sudoers/autologin/user/polkit rule leaking into the installed system turns M4 red.
- A5 vs owner decision: always create a separate SecLegion ESP (never write to Windows' ESP); refuse MBR / too-small free space.
- Vendor apps: Microsoft VS Code licence likely forbids redistribution → fetcher packages with pinned sha256; `docs/third-party.md`; vendor SLA in canary; Wayland + sandbox smoke tests.
- Licensing: SPDX-MIT headers, `reuse lint`, `docs/PROVENANCE.md`; owner's current config can't be copied (derivative of unlicensed kartik317).
- Arabic keybind aliases by keycode; guide screen warns that disabling Secure Boot can trigger BitLocker recovery.
