# ISO #12 Implementation Plan: live desktop, installer redesign, existing partitions

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or
> superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for
> tracking.

**Goal:** fix the owner's three metal findings on ISO #11 (Try Live boots stock Hyprland, the installer says
"not booted in install mode", the installer looks unbranded and cannot use a ready partition), ship them in
ISO #12, then finish the remaining 1.0 and 1.1 items.

**Architecture:** the backend stays as it is: the configurator writes archinstall JSON, and the GUI stays a
pure-Python model with GTK views. The redesign swaps the view layer to libadwaita, and the model's page keys
and fragments keep their shape. The new "replace a partition" mode reuses the alongside path: the chosen
partition's extent becomes the gap, and that partition is marked `delete`.

**Tech Stack:** Python 3, GTK 4.24 and libadwaita 1.10 (PyGObject 3.58), archinstall (ISO version),
archiso, QEMU/OVMF VM gates, pytest.

**Spec:** the owner's reports of 2026-11-03 and 2026-11-04 are quoted in §0. The rules come from `CLAUDE.md`.

## Global Constraints

- Official Arch repos and `[seclegion]` only. libadwaita comes from extra and is already in
  `iso/packages/desktop.list`.
- No sudo, no pacman (except `-Si`/`-Q`), no `/etc` edits, and no writes to a physical disk. VM disks go
  under `/var/tmp/seclegion-build/vm` only.
- Containers start only through `tools/docker-build.sh`. Stop a build only with `docker stop --time 600`.
- Lint is green before every commit, with lines ≤ 110. Evidence PASSes are recorded on a clean committed
  tree only.
- Implementers are Sonnet 5.5 (medium) in worktrees. The main session (Opus) reviews and re-runs every gate.
  There are no reviewer subagents. At most 2 lanes.
- The installer GUI never imports archinstall and never writes disks. Pages only produce fragments, and
  `configurator.validate` is the only judge of safety.
- Every new refusal fails closed: a partition the installer could not identify is not offered.
- Colours come from `desktop/theme/tokens.toml`, never hand-copied hex. The logo is
  `desktop/branding/seclegion-logo.png` (owner artwork, all rights reserved).

## Phase B: install-mode detection on real hardware

### Task B1: install mode no longer depends on the target being `active`

**Likely cause (to be confirmed in step 1):** `facts.gather` asks `systemctl is-active
seclegion-install.target` once, when the GUI starts. The target has `Wants=multi-user.target`, so on a
laptop with no cable it stays `activating` until network-online times out. The kiosk is already up by
then, so every disk is refused with `not_install_mode`. In the VMs the network comes up at once, so all
36 gates passed.

**Files:**
- Modify: `installer/installd/facts.py` (`gather`, new `detect_install_mode`)
- Modify: `installer/ui/seclegion-installer-gui` (re-gather facts when the disk page is entered)
- Test: `tests/install/test_facts_install_mode.py` (new), and a VM gate in `tests/iso/test_m2_targets.py`

**Interfaces:**
- Produces: `facts.detect_install_mode(cmdline: str, target_state: str) -> bool`. It is True when `cmdline`
  contains `seclegion.mode=install` and `target_state` is in `("active", "activating")`, and False otherwise.
  A Live or Rescue cmdline is False whatever the target state.

- [ ] **Step 1: confirm the cause** in a VM booted with `-nic none`: read `systemctl is-active
  seclegion-install.target` 20 s after the kiosk appears. Expect `activating`. If it is `active`, stop and
  report: the cause is elsewhere (the live agent's photos then say which entry the owner booted).
- [ ] **Step 2: failing tests**

```python
@pytest.mark.parametrize("cmdline,state,want", [
    ("BOOT_IMAGE=x seclegion.mode=install systemd.unit=seclegion-install.target", "activating", True),
    ("BOOT_IMAGE=x seclegion.mode=install systemd.unit=seclegion-install.target", "active", True),
    ("BOOT_IMAGE=x seclegion.mode=install", "inactive", False),
    ("BOOT_IMAGE=x seclegion.mode=live systemd.unit=seclegion-live.target", "active", False),
    ("BOOT_IMAGE=x seclegion.mode=install", "failed", False),
])
def test_detect_install_mode(cmdline, state, want):
    assert facts.detect_install_mode(cmdline, state) is want
```

- [ ] **Step 3:** implement it, and have `gather()` read `/proc/cmdline` and the target state through `_out`.
- [ ] **Step 4:** the unit tests pass, and `tests/install` stays green.
- [ ] **Step 5:** add the VM gate `test_m2_install_mode_without_network` (boot Install with `-nic none`,
  run `seclegion-configure --gather-facts`, expect `"install_mode": true`). Commit.

## Phase C: install into a partition the owner prepared

### Task C1: backend mode `partition`

**Behaviour:** the user picks one existing partition. It is deleted, and a new ESP plus the btrfs root
are created in its exact extent, so the code is the alongside layout with that extent as the gap. The
other partitions stay `existing`. Windows keeps its own ESP, and `winboot.py` adds its boot entry, as in
alongside.

**Files:**
- Modify: `installer/installd/configurator.py` (`Answers.mode`, the new field `Answers.partition`,
  `validate`, `build_config`, `summary`, `post_hints`)
- Modify: `installer/installd/seclegion-configure` (a `--partition` flag in the CLI answers)
- Test: `tests/install/test_plan.py` (new cases), a fixture `tests/install/fixtures/facts_partitions.json`
  (the Legion layout: NVMe1 with EFI 260 MiB, MSR, NTFS C:, NTFS recovery, and an empty 200 GiB ext4)

**Interfaces:**
- Produces: `Answers(mode="partition", partition="/dev/nvme1n1p5", ...)`. `effective_mode` is
  `"partition"`.
- Produces: `configurator.partition_choices(disk: dict, facts: dict) -> list[tuple[str, int, str | None]]`.
  Each item is (partition path, size in bytes, refusal code or None), in disk order. The GUI (Task D4) shows
  this list and greys out every item with a refusal.
- Refusal codes (new):
  - `no_such_partition`: the partition is not on the chosen disk.
  - `part_mounted`: the partition is mounted.
  - `part_is_esp`: the partition type is ESP_GUID.
  - `part_is_windows`: ntfs, bitlocker, MSR GUID `e3c9e316-0b5c-4db8-817d-f92df00215ae`, or recovery GUID
    `de94bba4-06d1-4d40-a16a-bfd50179d6ac`.
  - `part_too_small`: under MIN_DISK (20 GiB).
  - `part_unknown`: no parttype and no fstype could be read.
- Confirmation: `answers.confirm` must equal the partition's kernel name (`nvme1n1p5`), not the disk model.

- [ ] **Step 1: failing tests**, one per refusal code, plus:

```python
def test_partition_mode_replaces_only_the_chosen_partition(legion_facts):
    cfg, _ = build_config(Answers(disk=NVME1, mode="partition", partition="/dev/nvme1n1p5",
                                  confirm="nvme1n1p5", username="u", password="p"), legion_facts)
    dm = cfg["disk_config"]["device_modifications"][0]
    assert dm["wipe"] is False
    status = {p["dev_path"]: p["status"] for p in dm["partitions"] if p["dev_path"]}
    assert status["/dev/nvme1n1p5"] == "delete"
    assert all(s == "existing" for d, s in status.items() if d != "/dev/nvme1n1p5")
    new = [p for p in dm["partitions"] if p["status"] == "create"]
    p5 = part(legion_facts, "/dev/nvme1n1p5")
    assert new[0]["start"]["value"] * MIB == aligned_start(p5)          # ESP at the partition's start
    assert sum(p["size"]["value"] for p in new) * MIB <= int(p5["size"])  # never past its end
```

- [ ] **Step 2:** run the tests. Expect FAIL with `bad_mode`.
- [ ] **Step 3:** implement it. Keep LUKS optional, as in alongside (`use_luks` follows `luks`).
- [ ] **Step 4:** the unit tests pass, and `make lint` is green.
- [ ] **Step 5: spike in the VM:** confirm that the ISO's archinstall accepts `status: "delete"` in a
  `default_layout` modification. If it does not, switch to `config_type: "manual_partitioning"` and say so in
  the report.
- [ ] **Step 6:** add the VM gate `test_i3_matrix.py::test_partition_mode` (a 60 GiB qcow2 with a
  pre-made 20 GiB ext4 and a 30 GiB "data" ext4. Install into the data partition. Assert that the ext4
  partition still mounts with its sentinel file, and that the installed system boots to the greeter).
  Commit.
