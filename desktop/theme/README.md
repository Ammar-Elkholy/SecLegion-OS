# seclegion-theme

Wallpaper-driven live theming. No daemon: one short run per change.

    seclegion-theme apply [--wallpaper IMG] [--mode auto|default] [--accent #hex] [--contrast normal|high] [--no-hooks]
    seclegion-theme current [--json]
    seclegion-theme reset

Install layout: package at `/usr/lib/seclegion/python/seclegion_theme`, launcher `tools/seclegion-theme`
(`#!/usr/bin/python3 -I`), `tokens.toml` at `/usr/share/seclegion/theme/`, static fallback files at
`/usr/share/seclegion/theme/default/` (this repo: `desktop/theme/default/`, regenerate with
`seclegion-theme export-default desktop/theme/default`; a test keeps it in sync). Every generated file
starts with an SPDX MIT header; `colors.json` cannot carry a comment, so the generator writes
`colors.json.license` (REUSE convention) next to it.

Modes: `auto` (from the wallpaper via matugen) and `default` (SecLegion Dark, static tokens). There is
no free-hue mode: `--accent` is accepted with `--mode auto` only, replaces the wallpaper colour as the
seed, and its hue is clamped into the family like any wallpaper colour. Without `--wallpaper`, the
current theme's wallpaper is reused (so `reset` and `--contrast high` keep the `wallpaper` link).

## Output contract (`$XDG_STATE_HOME/seclegion/theme/current/` -> `<hash>/`)

| file | content |
|---|---|
| `colors.json` | `{schema, mode, requested_mode, contrast, source{wallpaper,sha256,accent_override}, tokens{...}}` |
| `colors.css` | `@define-color sl_<token> #rrggbb;` for every token |
| `hyprland-colors.lua` | `return { active_border, inactive_border, bg, surface, text, accent, accent2, crit, shadow }`, all `"rgba(rrggbbaa)"`, never `0x` |
| `kitty-colors.conf`, `rofi-colors.rasi` (`sl-<token>`), `hyprlock-colors.conf` (`$sl_<token> = rgba(...)`), `swaync-colors.css`, `swayosd-colors.css` | per-app colour definitions (swaync/swayosd add `sl_notif_*` / `sl_osd_*`) |
| `starship-palette.toml` | the `[palettes.seclegion]` table alone |
| `gtk3.css`, `gtk4.css` | GTK `@define-color` overrides for GTK 3 and GTK 4/libadwaita |
| `kde.colors` | KDE colour scheme (`[Colors:*]` groups) |
| `qt6ct.conf` | a qt6ct colour scheme (`[ColorScheme]`), not qt6ct's main config: install it as e.g. `~/.config/qt6ct/colors/SecLegion.conf` and pick it in qt6ct's Appearance tab |
| `yazi-theme.toml` | whole yazi theme; line 1 is the ownership marker `# generated by seclegion-theme`, line 2 the SPDX line. Sections follow yazi 26.9.1 (`mgr`, `indicator`, `pick`) |
| `regreet.css` | the ReGreet (greetd) GTK4 style sheet: every token as `@define-color sl_<token>`, then rules that use only those names, no `@import`. The ISO build installs the **default export** as `/etc/greetd/regreet.css` inside the image (`iso/profile/airootfs/etc/greetd/regreet.css`, kept equal by `tests/iso/test_regreet.py`); the host never gets it and no host tool touches the display manager |
| `wallpaper` | symlink to the source image (absent when none was given) |

**yazi hook.** After each apply, `hook_yazi` copies `yazi-theme.toml` to `$YAZI_CONFIG_HOME/theme.toml`
(else `$XDG_CONFIG_HOME/yazi/`, else `~/.config/yazi/`). It runs by default (the other hooks have no
enable switch either). Ownership rule: the marker on line 1 *is* ownership. Next to `theme.toml` the hook keeps three files:
`theme.toml.seclegion-sha256` (sha256 of what it last wrote), `theme.toml.seclegion-bak`, and
`theme.toml.seclegion-orig`.

- Absent file: created.
- First line is the marker: ours, replaced. If it differs from the sidecar hash (you edited it below the
  marker), the edited copy is first saved to `theme.toml.seclegion-bak` (the previous `.bak` is
  overwritten) and the hook reports `ok-backed-up` with the path. To opt out of management, delete line 1 *and*
  create `theme.toml.seclegion-orig` (even empty); without it the next apply adopts the file.
- No marker, regular file, and no `theme.toml.seclegion-orig`: first run. yazi 26.9.1 ignores the old
  `[manager]` section, so such a file is dead config; it is renamed (mode kept) to
  `theme.toml.seclegion-orig`, ours is written, and the hook reports `adopted` with the restore
  command `mv theme.toml.seclegion-orig theme.toml`.
- No marker and `theme.toml.seclegion-orig` already exists: you restored or edited it on purpose; left
  alone (`kept`).
- A symlinked `theme.toml` or a symlinked yazi config dir is never followed or written (`kept`), so a
  link to a dotfiles repo is safe. Missing config dir and no `yazi` on PATH: skipped.

Writes (also the sidecar and `.bak`) go through an exclusive, no-follow temp file in the config dir,
fsync, `os.replace`, then a best-effort fsync of the directory; a replaced marker file keeps its mode.

**File manager fragments** (`desktop/fm/`): `dolphinrc` uses `ShowStatusBar=FullWidth` because Dolphin
26.08 has no `ShowSpaceInfo` key; free space is shown in the full-width status bar.

Extra file beyond the contract: `starship.toml`, the whole starship config (starship has no include),
generated from a fixed template plus the palette table. The only commands it embeds are the fixed
`custom.vpn` strings (`ip ... tun0 | awk | cut`, `ip link show tun0`); no token, path or other input
ever reaches them.

Tokens: `bg surface surface2 text muted accent accent2 border_active border_inactive ok warn err crit ansi0..ansi15`.
Hyprland config should load the Lua with `pcall(dofile, ...)` and fall back to
`/usr/share/seclegion/theme/default/hyprland-colors.lua`.

## Guarantees (same clamps for default and auto)

- Identity, checked by `violations()` on the final 8-bit colours with zero tolerance in every mode:
  accent/accent2 OKLCH hue inside `ACCENT_HUE_RANGE` (150..205, tunable in `palette.py`), bg L <= 0.18.
- WCAG 2.x on the final 8-bit colours: text >= 4.5 (aims 7), muted/accent/ANSI >= 4.5, active border >= 3;
  `--contrast high` raises all of these to 7. Inactive border is exempt from 3:1 (inactive component) except in high.
- ok/warn/err/crit are fixed (>= 4.5 on bg/surface, cannot reach 7); when they would fail, the dark base is darkened.
- Colours reach templates only via a strict `^[0-9a-f]{6}([0-9a-f]{2})?$` check.

## Runs, state and live reload

- One flock (`$XDG_RUNTIME_DIR/seclegion-theme.lock`) covers the whole apply: reading
  `current/wallpaper`, matugen, render, write, swap, prune and hooks. Concurrent runs are serialised;
  the last one to take the lock is the one left in `current`. A waiting run gives up after 40 s.
- Each file and the temp dir are fsynced before the rename into `<hash>/`. An existing `<hash>/` is
  reused only if every contract file is non-empty and `colors.json` parses; otherwise it is rebuilt.
  Under the lock, the newest 5 theme dirs plus `current`'s target are kept and stale `.tmp-*` removed.
- kitty (SIGUSR1) and waybar (SIGUSR2) are signalled only for pids with our uid, the expected comm,
  `/proc/<pid>/exe` basename exactly `kitty`/`waybar`, and the same `WAYLAND_DISPLAY` as this run. No
  `WAYLAND_DISPLAY`: no signals. No `HYPRLAND_INSTANCE_SIGNATURE`: no hyprctl.
- swayosd is restarted only through its active systemd user unit (`swayosd.service`, else the first
  active `swayosd*` unit); a swayosd-server started any other way is skipped ("restart manually to
  restyle"). No hook leaves a process behind.

## Owner decisions

- Inactive border keeps the owner look (`border_inactive` = surface): exempt from 3:1 in normal mode
  (WCAG 1.4.11 inactive component), held to 3:1 against bg in `--contrast high`. Owner to confirm.

## Known low-severity items (from Sec review round 2)
- The swayosd hook can make up to three 2 s calls, so it can overrun the hook pool budget and finish after the lock is released. It should use one shared deadline.
- The lock path depends on `XDG_RUNTIME_DIR`. A run without it uses a different lock file. Run the tool from the user session, or move the lock under the state root.
- When three or more applies are queued, the last one requested is not guaranteed to win, because waiters poll a non-blocking flock.
- Smaller gaps: pid reuse between the target check and the signal (pidfd would close it); `kitty (deleted)` after an upgrade is skipped; stale `.current.<pid>` links are not pruned.
